# 研究生桌面模拟器 · GradOS

在一张可以自由切换软件的桌面上，度过四周研究生生活。先提出问题，再用有限的时间与算力验证它；也可以认真做工程、结识同门，或者给自己放个假。

当前支持本地离线试玩，源码保存在 GitHub 私有仓库；按用户要求新增 GitHub Pages 在线试玩部署。

源码仓库：[LeP-Ton/graduate-desktop-simulator](https://github.com/LeP-Ton/graduate-desktop-simulator)，默认分支 `main`。

## 在线试玩部署

使用独立的公开 Pages 仓库 `LeP-Ton/graduate-desktop-simulator-pages` 托管构建产物，源码仓库保持私有。执行 `npm run package:pages` 生成 `artifacts/pages/`，将其发布到试玩仓库的 `main` 分支，Pages 来源选择根目录。Vite 使用相对资源路径，适配项目子目录。

当前构建与本机子目录试玩验证通过，公开仓库创建被自动审批拒绝，等待用户明确授权公开这 5 个构建文件；尚无已部署的在线地址。

线上存档保存在访问者自己的浏览器中，与离线版分开；跨版本转移进度请导出、导入 JSON。

## 本地运行

需要 Node.js 20+。

```bash
npm install
npm run dev
```

浏览器访问终端打印的地址。`npm run build` 做类型检查与生产构建；`npm test` 执行核心规则验证。游戏无需真实 GPU、模型 API 或学术数据库。

也可执行 `npm run package:local` 生成 `artifacts/GradOS-即点即玩.html`，使用 Chrome 双击离线试玩，不需要启动服务器。这个文件使用独立的本地存档；与服务器版本互相转移进度时，请使用 JSON 导出和导入。

## 如何开始

1. 创建身份，分配 12 点能力，选择三个研究方向之一与导师风格。
2. 在学术搜索精读相关论文，理解方法与局限；收藏和引用会同步进入知识库与论文。
3. 在研究工作台选择课题，然后在 IDE 编写并测试实现。
4. 在实验终端配置模型、数据、方法、学习率、轮数、批大小、服务器和随机种子。
5. 训练进入共享 GPU 队列。切换软件、回消息或睡觉都可以让任务继续。
6. 导入结果，分析曲线与因果诊断；将图表与引用加入论文，完善章节后选择目标投稿。
7. 根据具体评审补实验并逐点回复。写作时间不能代替可信证据，也不能保证接收。

时间默认暂停。每个工作动作有模拟时间成本；底部播放键每两秒推进 15 分钟，可选择加速。一小时快进和八小时睡眠都使用同一时间引擎。双击窗口标题栏最大化，拖动移动，黄色按钮最小化，程序坞切换应用。`⌘/Ctrl + K` 打开启动器，`Alt + Tab` 在打开的窗口间切换。

## 一个可以复盘的科研案例

以「有限预算下的可靠工具调用」为例：阅读工具验证、数据污染与复现准则文献，提出自适应验证假设。使用轻量模型、清洗集、学习率 0.001、8 轮、batch 16，先建立基线；保持其他配置和 seed 不变，仅改为自适应策略。

若训练过久，验证损失会回升；若使用原始数据，表面分数会虚高；若模型和 batch 超出显存，任务无法启动。每种失败都有可检查的原因。不同 seed 的重复实验和跨领域测试能够补齐证据。再引用读过的相关工作、插入图表、完善论文并投稿。首次证据不全可能收到大修，补齐证据再重投可以接收。

这只是一个可走通的案例。不同方法、模型规模、硬件、投稿目标和导师有各自的资源收益与机会成本；没有预设职业路线。

## 软件与数据联动

- 研究工作台、通讯、学术搜索、文献管理、IDE、实验终端、GPU 管理器、数据分析、论文编辑器、日历、邮箱、文件管理和培养系统。
- 另外提供规则模拟 AI 助手、校园生活与存档设置。AI 生成可以提高效率，也可能制造错误代码、虚构引用和夸大结论，核验有时间成本。
- 七名 NPC 按独立日程和能力推进研究，导师主动追问、同门共享资源、管理员维护服务器；合作影响代码与关系。
- 每周组会、课程、实习交流和横向项目会形成真实日程冲突。生活影响精力、健康、压力、工程经验与人际积累。
- 第 28 天结束后展示月度回顾，论文、工程、合作与生活都计入成长，不设唯一胜利条件。

## 存档

进度自动保存在当前浏览器的本地存储中；设置中可以保存和读取一个独立手动快照，以及导入、导出 JSON。存档包含种子、队列、实验结果、NPC、日程、文稿和审稿快照。导入前进行结构与引用校验。存档不会在设备间自动同步，清理浏览器数据前请先导出。

## 架构与范围

- `src/game/state.ts` 与 `types.ts`：游戏状态与初始化。
- `time.ts`、`events.ts`、`npc.ts`、`gpu.ts`：时间、事件、NPC 与计算队列。
- `research.ts`、`writing.ts`：可解释实验、证据判断、审稿与论文整理。
- `engine.ts`：统一动作入口；`random.ts` 与 `storage.ts`：确定性随机源和本地存档。
- `data.ts`：虚构论文、课题、导师、NPC、实验配置与投稿目标。
- `src/components/`：软件界面，规则通过动作入口执行。

首版为四周 MVP。IDE、实验、AI 与评审均为游戏规则模拟；本期不执行真实 Python，也不进行真实学术投稿。三年培养、毕业答辩、复杂关系剧情、博士模式、真实 AI 与多人科研列入后续范围。
